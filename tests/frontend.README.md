# 离线前端检查

在项目目录运行：

```sh
python3 scripts/test_frontend.py
```

Windows 可以使用 `python scripts/test_frontend.py`。

测试脚本会使用已经安装的 Node.js / NodeJS；如果找不到，会尝试 macOS 自带的 JavaScriptCore。可用 `--runtime /已有运行时的绝对路径` 显式选择 Node.js 或 JavaScriptCore。脚本不安装任何软件。若两种运行时都不存在，退出码为 2，提示缺少可选的测试运行时；应用本身仍然只依赖 Python 标准库。

## 覆盖内容

共 39 项检查，直接读取生产 `public/app.js`，将启动时的数据刷新替换为测试驱动，并使用内存中的最小 DOM 与严格的模拟请求队列。所有请求由测试数据返回；出现未声明的请求会立即失败。

- 空房间引导、官方赛程来源、赔率留空和双边填写规则。
- 已配置赔率、未知赛制、开赛封盘、主队与搭子主队标记。
- 主队筛选、战队搜索、UTC+8 日期边界、内容转义。
- 同步预览勾选、已导入去重标记、警告信息、日期与超时参数。
- 官方无赛程错误后的日期保持、日期切换清除旧结果。
- 空结果、超时、日期切换或关闭弹窗后的过期响应。
- 手动建赛赔率为空时提交 `null`、只导入已勾选的官方编号。
- 已导入的官方对局可显式勾选更新，默认不勾选。
- 状态刷新乱序、保存完成后旧响应返回、旧请求失败和操作被拒绝后的数据核对。
- 赛后讨论入口与空状态、按场选择、文本转义、作者撤回按钮和赛果更正背景。
- 按玩家和比赛分别保留草稿、刷新和失败重试保护、发布请求与清空赛季后的草稿处理。

测试全部完成后会输出 `NEXUS_FRONTEND_TESTS_OK`。Python 运行脚本同时核对退出码和此标记，避免部分 macOS JavaScriptCore 在 `quit(1)` 时仍返回零退出码造成漏报。

这些检查验证逻辑、HTML 输出与模拟事件，不运行浏览器、不发起 HTTP 连接，不验证视觉布局、浏览器原生控件或真实交互效果，也不会修改本机积分数据库。
